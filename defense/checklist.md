# Defense Checklist

## Mobile / API
- [ ] Ніяких секретів в APK — логіни, паролі, токени не повинні бути в коді додатку,
      бо APK може завантажити і розпакувати будь-хто
- [ ] Static analysis у CI: `gitleaks`, `MobSF`, `apkleaks` — автоматична перевірка
      коду на секрети при кожному коміті, до того як потрапить у продакшн
- [ ] Ротація API credentials при релізі — навіть якщо старий пароль витік,
      він вже не працює
- [ ] Certificate Pinning — додаток приймає відповіді тільки від конкретного сертифіката,
      щоб не можна було перехопити трафік через підставний сервер

## Web Application
- [ ] Параметризовані запити для всього SQL включно з ключами масивів —
      дані ніколи не вставляються напряму в SQL-рядок
- [ ] Whitelist допустимих filter/sort значень — якщо в URL очікується число 490,
      приймати тільки конкретний список чисел, все інше — помилка
- [ ] Всі AJAX-ендпоінти вимагають авторизацію — анонімний запит не повинен
      отримувати жодних даних, навіть "нешкідливих"
- [ ] API не повертає конфіг-об'єкти — відповідь містить тільки потрібні поля,
      ніяких $CFG, ніяких системних шляхів, ніяких версій ПО
- [ ] `realpath()` + перевірка межі папки для file input — переконатись що файл
      знаходиться в дозволеній папці, а не десь в /etc через ../../../
- [ ] Валідація файлів: розширення + магічні байти — перевіряти не тільки назву файлу
      але й перші байти вмісту, бо PNG можна назвати .php
- [ ] `phar://` wrapper відключений — PHP не буде автоматично десеріалізувати
      метадані архівів, навіть якщо хтось передасть phar:// шлях
- [ ] `unserialize()` з whitelist або замінити на JSON — обмежити які класи PHP
      може відтворити при десеріалізації, або взагалі не використовувати serialize
- [ ] Upload-директорія: заборона виконання PHP — навіть якщо хтось завантажить
      PHP-файл, сервер поверне його як текст а не виконає

## Auth & Access
- [ ] B2B реєстрація — ручна модерація — новий постачальник не отримує доступ
      автоматично, адмін підтверджує кожен акаунт вручну
- [ ] Password reset: TTL 15 хв, одноразовий, rate limit — посилання для скидання
      пароля живе 15 хвилин, після використання стає недійсним, не можна
      генерувати сотні таких посилань підряд
- [ ] MFA для Grafana, Zabbix, Jenkins, GitLab — навіть якщо пароль витік,
      без другого фактора зайти не можна
